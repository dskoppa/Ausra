# Aušra library-first implementation plan

Aušra is currently a Go standard-library server with a vanilla JavaScript UI and JSON-file state. The entries below are planned choices unless marked implemented. Add each dependency with the feature that needs it. Keep the dawn theme, domain models, workflow semantics, and explanatory connection views specific to Aušra; use libraries for common components and protocols.

| Capability | Preferred library or SDK | Current replacement point | Adoption check |
| --- | --- | --- | --- |
| UI application | [React](https://react.dev/learn/describing-the-ui), TypeScript, and [Vite](https://vite.dev/guide/) | `web/app.js` and static HTML | Preserve working screens, themes, URLs, and keyboard flow in the Docker image. |
| Accessible UI controls | [Radix Primitives](https://www.radix-ui.com/primitives/docs/overview/introduction) with Aušra CSS tokens | Hand-built dialogs, menus, tabs, selects, and tooltips as they appear | Verify focus handling, keyboard operation, and screen-reader names. |
| Server data in UI | [TanStack Query](https://tanstack.com/query/latest/docs/framework/react/overview) | Manual fetch, cache, polling, loading, and error handling in `web/app.js` | Refetch run state correctly and stop polling on unmount. |
| Dense tables and forms | [TanStack Table](https://tanstack.com/table/latest/docs/introduction) and [React Hook Form](https://react-hook-form.com/get-started) with [Zod](https://zod.dev/) | Planned inventory, connection, policy, and job screens | URL-backed filters, accessible validation, and matching server validation. |
| Workflow canvas | [React Flow](https://reactflow.dev/learn) (`@xyflow/react`) | Planned graph editor | Offer an ordered list editor for the same workflow and validate graph rules on the server. |
| Git source (implemented) | The maintained Git CLI already present in the Docker image | `repositories.go` uses `git clone`, `fetch`, `rev-parse`, and disposable `worktree` checkouts | Pin the commit when a run is requested and verify sync cannot change it. This delegates Git transport and object handling to Git rather than implementing those protocols in Go. |
| GitHub webhooks (implemented) | [google/go-github](https://github.com/google/go-github) v68 | `webhooks.go` uses `ValidatePayload` and `ParseWebHook`; Aušra code maps push events to its own jobs and workflows | Verify signatures, matching repository/ref/commit, duplicate delivery IDs, rotation, approval-gated runs, and failure handling. v68 supports the project's Go 1.22 target. |
| Webhook replay ledger (implemented) | [bbolt](https://github.com/etcd-io/bbolt) v1.3.11, MIT licensed | `delivery_ledger.go` keeps all accepted IDs beyond the 1,000 recent deliveries in JSON state | Verify duplicates after eviction and restart, and preserve retry of failed deliveries. The Go 1.22 compatible 1.3 release avoids changing the project's source toolchain. |
| Webhook request rate limit (implemented) | [golang.org/x/time/rate](https://pkg.go.dev/golang.org/x/time/rate) v0.10.0, BSD licensed | `webhooks.go` limits each configured repository before reading the event body | Verify 429 and `Retry-After` without recording or starting a rejected delivery. |
| PostgreSQL access | [pgx](https://github.com/jackc/pgx), [sqlc](https://docs.sqlc.dev/), and [Goose](https://pressly.github.io/goose/) | `main.go` JSON-file persistence | Transactional migrations, scoped queries, restart recovery, and a restore test. |
| SSO/OIDC | [go-oidc](https://github.com/coreos/go-oidc) and [golang.org/x/oauth2](https://pkg.go.dev/golang.org/x/oauth2) | Environment-supplied single-admin login | Verify provider metadata and tokens, enforce state/nonce/PKCE, test group revocation, and keep a recovery path. |
| Passwords and sessions | [golang.org/x/crypto](https://pkg.go.dev/golang.org/x/crypto) for password hashing; evaluate a maintained session library when named accounts are added | Prototype admin password and cookie handling | Hashed passwords, expiry, revocation, CSRF protection, and rate-limit tests. |
| AWS and EKS identity | [AWS SDK for Go v2](https://docs.aws.amazon.com/sdk-for-go/v2/developer-guide/) | Planned account, role, STS, and EKS connections | Validate the exact principal, account, role, cluster, and denied paths. |
| Kubernetes API | [client-go](https://github.com/kubernetes/client-go) | Planned cluster operations | Pin cluster and namespace, use short-lived auth, test RBAC denial and private endpoint errors. |
| Azure and Google Cloud | [Azure SDK for Go](https://learn.microsoft.com/en-us/azure/developer/go/overview) and [Google Cloud Go client libraries](https://cloud.google.com/go/docs/reference) | Planned cloud connections | Exercise workload identity, refresh, scope, and permission-denied paths. |
| External secrets | Official [Vault Go client](https://developer.hashicorp.com/vault/api-docs/libraries) and provider secret-manager SDKs | Planned credential references | Keep secrets out of read APIs, logs, and exports; test rotation. |
| Policy evaluation | [Open Policy Agent Go SDK](https://www.openpolicyagent.org/docs/integration) | Planned policy gates | Version policy decisions and test allow, deny, and approval requirements. |

Use the Go standard library when it already provides a clear, well-supported solution. A router or scheduler dependency is justified only when actual requirements exceed the current implementation. Do not add a second framework just to replace a few working lines.

The command-center overview extends the existing vanilla JavaScript UI because its cards, project relationships, and activity feed are Aušra-specific views over APIs already in the prototype. The planned React migration remains a separate vertical slice so the Docker UI stays working during this checkpoint.

Adopt in vertical slices: (1) PostgreSQL and migrations with existing UI behavior retained; (2) named identities, SSO, and authorization; (3) cloud credentials and EKS via SDKs; (4) React UI shell and accessible components; (5) workflow canvas and policy engine. Each slice needs a working Docker build, relevant tests, and an updated checkpoint.
